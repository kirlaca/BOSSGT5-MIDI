GT-5 Editor · Web MIDI

User guide

An editor for the BOSS GT-5 guitar multi-effects (1996) that runs entirely in the browser. The patch's effects appear as pedals, in the order of the patch's own effect chain. The browser talks to the GT-5 directly through a USB-MIDI interface: nothing to install, no server.

Status (23 Oct 2026): tried with a real GT-5 through a USB-MIDI interface. What works and how is below – the GT-5 is fussier over MIDI than later BOSS units: it can't be asked for its patches (it sends them only with a Bulk Dump started on the unit), and it stores patches only on its BULK LOAD page. Before writing anything, take a full Bulk Dump and keep it as a file (section 10).

What is this?

A browser version of the old Qt GT-5 FxFloorBoard. It sends the same MIDI messages and reads and writes the same .syx files, but it is a single web page that runs in Chrome or Edge on any computer.

It has four pages, on the tabs below the header:

  • Effects: the patch's 15 effects as pedals, the chain order and every effect parameter;
  • EXP / CTL / Assign: what the expression pedal, the CTL pedal and the 8 assigns control;
  • Library: all 250 patches in a list; read, write, copy and save many at once;
  • System: the GT-5's own settings (tuner, output, MIDI, manual mode, the custom OD/DS and preamps, the user harmony scales).

1What you need

  • Browser: Chrome or Edge on Windows, macOS, Linux or Android. Safari and iPhone/iPad won't work – they have no Web MIDI.
  • A USB-MIDI interface. A decent, opto-isolated one (e.g. Roland UM-ONE mkII). Cheap "USB2.0-MIDI" cables often pass program changes but not SysEx (patch read and write).
  • On Android also a USB OTG adapter.

Wiring

Computer / phoneUSB USB-MIDI interface2 × DIN GT-5 rear panel
interface OUT→GT-5 MIDI IN
interface IN←GT-5 MIDI OUT

The two plugs go in crossed over. Some cables are labelled the other way round – if patch changes don't work, swap them. The editor needs both directions: without the GT-5's MIDI OUT it can send but not read.

2Starting

The editor is index.html in the webmidi folder. Three ways to open it:

  • From a web address (HTTPS): if it is hosted somewhere, open its address. This is also how it works on a phone.
  • Straight from the file: double-click index.html. If the browser doesn't ask for MIDI access this way, use the next option.
  • From a local server: in the project folder run node tools/serve.mjs and open http://localhost:8000/. (Any static web server will do; no Python needed.)

On Windows only one program can use a MIDI port at a time. If the Qt FloorBoard or a DAW holds the interface, close it.

3Connecting to the GT-5

  1. Click Offline in the top right corner.
  2. The first time, the browser asks for permission to use MIDI devices (and SysEx): allow it. If you blocked it by mistake, re-enable it in the site settings (the icon at the left of the address bar).
  3. Either:
    • Auto-detect: looks for the GT-5 on every port and all 32 device IDs and connects by itself. Needs working SysEx in both directions.
    • By hand: pick the Output (to GT-5) and Input (from GT-5) ports, the Device ID and the Patch change channel (the GT-5's MIDI receive channel), then Use these ports.
  4. Once connected the label turns green and shows the port and device ID. Go offline disconnects.
  5. Right after connecting the GT-5 switches to the patch shown in the editor. The editor can't read it from the GT-5 (section 9): until the patches came in with a Bulk Dump (or from a saved dump file), the label shows not read and edits are not sent, so the editor's default patch can't replace your own sound.

The editor remembers the ports and reconnects on reload if the interface is plugged in. Unplug it and it goes offline. While offline every edit stays in the editor.

Check: after connecting, change patch with ◀ ▶. If the GT-5's display follows, patch changes work. The connection dialog has a MIDI log of everything that goes out (→) and comes in (←): switch patches on the GT-5 with its footswitches and they show up there if its MIDI OUT reaches the computer.

Auto-detect takes the patch change channel from the device ID (device ID 1 = channel 1). Whether that always holds on the GT-5 is not checked yet – if patch changes don't work, set it by hand to the GT-5's MIDI receive channel.

5Effects page

Patches (the patch map)

User and Preset view, one group (5 banks × 5 patches) per page, paged with ‹ ›. Patches not read yet show an empty, dimmed slot with only their number; when connected, selecting one reads it from the GT-5. A dashed yellow border marks a patch changed only in the editor (e.g. loaded from a file or written offline) – the GT-5 still holds the old one.

FX Chain

On the GT-5 the order of all 15 effects is set per patch. The bar shows the patch's own order, and the pedals stand in it too. Drag an effect to its new place, or focus it and move it with Alt + ← / →. Clicking an effect opens its detail panel.

At the end of the row is the Master module: the patch's output level.

  • On / off: click the pedal's footswitch. A pedal that is on lights its CHECK LED and a red bar below it.
    • Live switch (a CC20…CC27 tag on the pedal): the pedal switches through an assign of the patch and a MIDI CC – at once, with the GT-5's LED. The layout is fixed: Assign 1–8 = CC#20–27 → OD/DS, PRE, EQ, FX2, DD, CE, RV, WAH.
    • Without a live switch switching off is heard at once, switching on only after Write (the LED blinks until then). The reason: an effect switched on by SysEx plays wrong on the GT-5 (clean, even the preamp's drive gone) until the patch is reloaded.
    • Write puts the live switches into the patch (the GT-5's temporary patch takes no assign changes). If the patch uses its assigns for something else (32 of the factory user patches do), the editor asks whether to replace them. After an FX2 or Wah type change, Write updates the switch's target too. All 100 user patches at once: Library → Select shown → Write to GT-5.
    • Live pedals only (right end of the FX Chain bar) shows only the 8 pedals with a live switch. It changes nothing else.
  • Type: on OD/DS, PRE, SP, FX2 and RV use the green ◀ ▶ window (click the name to pick from a list); on FX1, CS, WAH, DD and TP the switch. Changing the type swaps the pedal's knobs.
  • Detail panel: a pedal only carries its main knobs. Click its name plate and a panel opens at the bottom with every parameter of that type, in groups. Esc or ✕ closes it.

Knobs: drag up or down with the mouse or a finger, use the mouse wheel (one step per notch), or focus one and use the keyboard: ↑ / ↓ one step, PgUp / PgDn a bigger step, Home / End minimum / maximum. On rate knobs the values above 100 are note values: 1/8 eighth, 1/8T triplet, 1/8. dotted.

6EXP / CTL / Assign page

These are part of the patch too: each patch can make the pedals do something different. On the left are the 10 controllers: the EXP pedal, the CTL pedal and Assign 1–8, each with whether it is on, what it controls and what moves it. For the selected one:

  • The switch next to its name turns it on and off.
  • Target: the 126 possible targets (effect on/off switches, the main parameters of every effect, the master and foot volume, manual mode, the tuner, MIDI start / stop), grouped by effect. Min and Max are shown in the target's own units – milliseconds for Delay Time, for example. Picking a new target sets Min to its minimum and Max to its maximum. With Min above Max the control should work the other way round (not yet checked on the unit).
  • Source (assigns only): what moves it – the EXP pedal, the CTL pedal, the external EXP/CTL pedals, the Internal Pedal, the Wave Pedal, MIDI velocity / pitch bend, or an incoming MIDI CC. Mode: Normal (follows the pedal) or Toggle (each press switches). The active range is the part of the source's travel the control acts in.
  • Response: the curve shows what target value each source position 0–127 gives.
  • Internal pedal: a virtual pedal that, when triggered (e.g. by a patch change or the CTL pedal), "presses itself" over the given time along the chosen curve. Wave pedal: moves the target continuously with the chosen waveform and rate. These cards are dimmed when they are not the source.

7Library page

All 250 patches in a table: name, PreAmp and OD/DS type, the FX-1 and FX-2 types when on, the effects that are on as coloured dots (in chain order), and the state:

  • Not read – not read from the GT-5 yet;
  • Editor only – changed in the editor, the GT-5 still has the old one;
  • Editing – the patch you are editing, with unsaved changes.

Filter at the top (User / Preset / All) or search by name. Click a patch number to open it on the Effects page. With patches ticked:

8System page

The GT-5's own settings, grouped as in the Qt program: Output (what amp / line the output feeds, and whether the speaker simulator follows the patch or is forced on or off), Global EQ / NS / Reverb (a correction for every patch), Tuner, Controls (dial function, the SUB CTL footswitches, assign hold), Patch change, MIDI (program change out and map, the pedals' CC output) and Manual mode (what the five footswitches switch).

Three GT-5 specialities are system settings too, shared by every patch that uses them:

  • Custom OD/DS 1 and 2 – the character (bottom, attack, top, type, low / mid / high) of the OD/DS types Custom 1 and Custom 2;
  • Custom PreAmp 1 and 2 – the voicing (bottom, top, volume type, 3-tone stack, clip, presence, gain, low / high, cabinet) of the preamp types Custom 1 and Custom 2;
  • User harmony scales – the 29 user scales of the Harmonist: pick one, then set the harmony for each of the 12 notes.
  • These are not patch settings: the GT-5 stores every change at once, so there is no Write here.
  • The GT-5 sends its system settings only in a Bulk Dump started on the unit; until one came in (or a file was loaded) the page shows the defaults.
  • Send all to GT-5 sends every setting shown (to restore a saved file, for example). Load file… / Save file…: all system settings in one file (1367 bytes, the FloorBoard's format).

9What reaches the GT-5, and when?

Tried on a real GT-5 (October 2026). The GT-5 handles MIDI its own way – this is what works:

WhatHow
Patch changeA Program Change at once; the GT-5 switches.
Live editing (knobs, switches, types, name, chain order)Goes straight into the GT-5's temporary patch, one parameter per message, each followed by a “Sound Change Request” – that makes it play at once, whatever the GT-5's display shows. A blinking dot on its display means the patch is edited. The GT-5 drops a parameter of a switched-off effect; for an effect with a live switch the editor sends it again when switching it on, the others play it after Write. The GT-5's EXIT button discards nothing. Not saved yet: changing patch loses it. EXP / CTL / Assign settings don't change in the temporary patch – they take effect only once the patch is written.
Saving what you hearEither Write in the editor (next row), or the GT-5's own WRITE button: it stores the temporary patch, live edits included.
Write / Write to GT-5The GT-5 stores patches only through its BULK LOAD page: UTILITY → MIDI → PARAMETER until BULK LOAD, which shows "waiting". The editor sends; the GT-5 shows "receiving". Then press EXIT: the GT-5 checks the data and stores it, which takes about 5 seconds. Sent while it plays normally, a write is ignored.
Reading patchesOnly with a Bulk Dump started on the GT-5 (UTILITY → MIDI → PARAMETER until BULK DUMP; choose the range, e.g. TEMP → TEMP for the current patch, or the whole memory). When asked by a program the GT-5 answers only the first block correctly and sends the rest in an internal format – the editor doesn't ask.
Revert, Init patch, loading a fileOnly what changed is sent, slowly. A whole different patch is more than the GT-5 can take live (its MIDI buffer overflows: "overflow" on the display, EXIT clears it) – the editor then doesn't send it: Write it, then select it.
System pageEvery change goes to the GT-5 at once.

10Saving and loading

Files go wherever the browser downloads to (usually Downloads), and you load them from wherever you like. The format is the Qt FloorBoard's .syx, so files move freely between the two programs.

  • Backup first: start a full Bulk Dump on the GT-5 (system + all user patches). The editor takes it in and goes to the Library page: Select shown → Save selected…, and System → Save file…. Long dumps can break off in the browser (see below); the dump then comes in more reliably with the small Windows tool in the project: python tools\gt5_tester.py receive --in DOREMiDi --file my-gt5.syx – and Load file… takes the whole dump (patches and system) into the editor.
  • Save file… (header): This patch, as edited, or All user patches in one file.
  • Load file… (header, or drop the file on the window): one patch goes into the editor, many into the user slots (Editor only until written), a system file to the System page, a full dump everywhere. Files with wrong checksums – common among old GT-5 files – load anyway.
  • You need a new dump only after changing patches on the GT-5 itself; what the editor wrote it knows.

11Troubleshooting

SymptomFix
"This browser has no Web MIDI"The browser has no Web MIDI (e.g. Safari, iPhone). Use Chrome or Edge.
"MIDI access denied"MIDI permission was blocked. Allow it in the site settings (the icon left of the address bar) and reload. If you opened the file directly and no prompt appears, start it from a local server (section 2).
"No MIDI ports found"The interface isn't plugged in or wasn't recognised. Plug it in and open the connection dialog again.
"could not open any MIDI input"Another program (the Qt FloorBoard, a DAW, another browser tab with the editor) holds the port. Close it and try again.
Nothing comes in any more – not even the GT-5's own patch changes in the MIDI logThe USB-MIDI interface's input got stuck (seen after long or broken SysEx). Unplug its USB plug, wait a few seconds, plug it back in.
A Bulk Dump breaks off in the browserTake it with tools\gt5_tester.py receive and load the file (section 10). If nothing comes in afterwards, replug the interface (row above).
The GT-5 shows "overflow"Its MIDI buffer filled up: too many changes in a row, or sent while it was in a menu. Press EXIT; edit on its normal display.
The GT-5 hangs on "DATA SENDING…"Something asked it for patch data (this editor doesn't; the old FloorBoard and its auto-detect do). Switch it off and on.
"no GT-5 patch data in this file"The file is from another unit (GT-3, GT-6 …) or not a patch file.
Patch changes don't workThe patch change channel differs from the GT-5's receive channel. Set it in the connection dialog.
Write did nothingThe GT-5 wasn't on BULK LOAD ("waiting") when the editor sent, or EXIT wasn't pressed afterwards (section 9).
The name on the display doesn't change while editingNormal: the GT-5 shows the stored name; the edited one appears when you press its WRITE button, and after storing.
A change was lost after changing patchWrite (or the GT-5's WRITE) before changing patch.
